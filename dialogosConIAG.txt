como pasar de un deque a una lista en python

from collections import deque

# Crear un deque
mi_deque = deque([1, 2, 3, 4])

# Convertir a lista
mi_lista = list(mi_deque)

print(mi_lista)  # Resultado: [1, 2, 3, 4]

y si quiero obtener los prrimeros N de la cola en una lista

from collections import deque
from itertools import islice

cola = deque(["a", "b", "c", "d", "e"])
n = 3

# Copia los primeros N elementos sin modificar la cola
primeros_n = list(islice(cola, n))

print(primeros_n)  # Resultado: ['a', 'b', 'c']
print(cola)        # La cola sigue igual: deque(['a', 'b', 'c', 'd', 'e'])

Cuales son los principales metodos de la libreria timeit en python pra medir tiempos
La librería timeit de Python sirve para medir tiempos de ejecución de fragmentos pequeños de código de forma precisa. Estos son sus métodos principales:

1. timeit.timeit()

Ejecuta un fragmento de código N veces y devuelve el tiempo total en segundos.

python
import timeit

tiempo = timeit.timeit(stmt="sum(range(100))", number=10000)
print(tiempo)  # ej: 0.234

Parámetros clave:

stmt: el código a medir (string o callable)
setup: código que se ejecuta una vez antes (imports, variables)
number: cuántas veces se repite (por defecto 1.000.000)
globals: para pasar el contexto actual, útil con globals=globals()
2. timeit.repeat()

Igual que timeit() pero repite la medición varias veces y devuelve una lista de tiempos. Es más confiable porque permite quedarse con el mínimo (menos afectado por ruido del sistema).

python
tiempos = timeit.repeat(stmt="sum(range(100))", number=1000, repeat=5)
print(min(tiempos))

En que afecta el number si la cantidad de elementos es siempre la misma

Buena pregunta, porque es una confusión muy común. number no cambia lo que hace tu código ni la cantidad de elementos que procesa. Lo que cambia es cuántas veces se ejecuta esa misma operación para poder medir con precisión.

¿Por qué existe number?

El problema es que operaciones pequeñas son demasiado rápidas para medirlas de forma confiable. Si sum(range(100)) tarda 0.000002 segundos, el reloj del sistema no tiene precisión suficiente y el resultado es ruido puro.

La solución de timeit es ejecutar la operación muchas veces y medir el tiempo total, que sí es medible con precisión.

python
# sum(range(100)) se ejecuta 10.000 veces
tiempo_total = timeit.timeit("sum(range(100))", number=10000)
# tiempo_total ≈ 0.02 segundos (medible)

tiempo_por_ejecucion = tiempo_total / 10000
# ≈ 0.000002 segundos por llamada
Entonces, ¿en qué te afecta?

En dos cosas prácticas:

1. Precisión de la medición

number muy bajo → resultado poco confiable, dominado por ruido del sistema.
number alto → promedio mucho más estable.

2. Cuánto tarda el benchmark en terminar

Si tu código tarda 1 segundo por ejecución y ponés number=1000000, vas a esperar 11 días.
Si tu código tarda 1 microsegundo y ponés number=10, no vas a medir nada útil.

Como funcionan los metodos sorted() o list.sort() en python:

Cómo funcionan sorted() y list.sort() en Python

Ambos ordenan elementos, pero tienen diferencias importantes.

Diferencia clave

list.sort() ordena la lista in-place (modifica la original) y devuelve None. Solo funciona con listas.

sorted() devuelve una nueva lista ordenada sin modificar el original. Funciona con cualquier iterable (listas, tuplas, strings, diccionarios, sets, generadores).
